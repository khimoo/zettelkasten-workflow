# CLAUDE.md

## 方針の決め方
- Zettelkasten方法論の唯一の情報源は https://zettelkasten.de/
- **既存ノートの慣習と zettelkasten.de が食い違う場合、zettelkasten.de を優先する。** 既存ノートは理想への途中経過であり、模倣すべき前例ではない。
- タスク（チェックボックス・Tasksプラグイン・globalQuery）に触れる前に `Tasks/タスク運用ルール.md` を読む。⏬や#dailyなどの目印の意味・不可視のdata.json設定はそこに書いてある。
- **ファイルの新規作成・編集を行う前に、変更内容（全文または差分）をチャットに提示して許可を取る。** 承認を得てから書き込む。勝手に書き込まない。

## Resources/ フォルダ（実務リファレンス）

`Resources/` は Zettel ではない実務の参照情報（住居契約・履修/単位・家電の説明書など）の棚。**Zettelkasten方法論・AI生成ノートの再調査ワークフローの対象外**。
- zettel化しない。StructureNote に接続しない。`ai_generated` プロパティも付けない。
- タグ・wikilink を付けない（Resources 内での相互リンクのみ可）。チェックボックス `- [ ]` を使わない。
- 更新される数値・日付は frontmatter に構造化する。詳細は [[Resources/README.md]]。

## AIが過去に間違えた箇所（再発防止リスト）

運用ルール: ここには**AIが実際に間違えたこと**だけを「間違い → 訂正ルール」の組で追記する。AIが放っておいても正しくできること（Vaultから推測可能な形式・慣習など）は書かない。ルールが自明になったら剪定してよい。

### 2026-07-10: topic tag を提案した
- **間違い**: 既存ノートのタグ（`#圏論` `#プログラミング` 等）から慣習を推測し、`#暗号化` `#secret管理` `#CLI` のような分野名タグ（topic tag）を提案した。
- **訂正ルール**: タグは **object tag のみ**。ノートが実際に扱う具体的なモノに付ける（`#sops` `#age` `#NixOS`）。分野・トピック名のタグは付けない。広い関連はタグではなく `[[wikilink]]` と StructureNote で接続する。
- **出典**: https://zettelkasten.de/posts/object-tags-vs-topic-tags/
- **注意**: 既存ノートに残る topic tag は負債であって前例ではない。ただし頼まれない限り勝手に直さない。

### 2026-07-14: 数式をLaTeX記法で書いた
- **間違い**: `$...$`/`$$...$$` の中身をLaTeX（`\forall` `\bigcup` `\overline{}` `\lambda` `\cap` `\neq` `\infty` `\blacksquare` 等）で書いた。このVaultの数式レンダラは**Typst**なので `unknown variable: orall` のようなエラーになり全く表示されない。
- **訂正ルール**: 数式は**Typst記法**で書く。バックスラッシュのLaTeXコマンドは使わない。対応の目安:
  - `\forall`→`forall`, `\exists`→`exists`, `\in`→`in`, `\subset`→`subset`
  - `\cap`→`sect`, `\cup`→`union`, 大きい演算子は `sect.big` / `union.big`
  - 添字は `union.big_(lambda in Lambda)`（複数文字の下付きは `_( )` で囲う）
  - `\overline{A}`→`overline(A)`, `\emptyset`→`emptyset`, `\neq`→`!=`, `\infty`→`oo`
  - `\lambda`/`\Lambda` はそのまま `lambda`/`Lambda`、カリグラフィは `cal(A)`
  - QED記号は `qed`等の組み込みが無いのでリテラル `∎` を使う
  - 区切りは既存ノートの慣習に合わせ**インライン `$...$`**（Vault内に `$$` 使用例は無い）
- **参考**: 既存ノートの実例は [[Zettel/J. Van Mill 4.3.md]]・[[Zettel/swelling.md]]（`sect.big_(U in cal(F))` `overline(V(U))` `emptyset` 等）。

### 2026-07-19: 仕様書の目次をzettelに転写した
- **間違い**: 背景知識を「概念ごと・仕様書の章ごと」に約25枚のzettelへ分解した。多くは対象（xodr等）の記述を章単位で切った破片＝仕様の写しで、ideaではなかった（後に12枚を統合・削除する手戻り）。
- **訂正ルール**: AIが知識ノートを新規作成する前に（「一括で全部作って」と言われても免除されない）、候補ごとに `lint-zettel` の「Zettel資格」ゲートを通す。失格候補は作らず、作成前に申告する。判定基準の本体は skill 側。

### 2026-07-19: 体験していないことを根拠として語った
- **間違い**: 軸順ノートを残す根拠として「変換で実際にハマった」と述べたが、変換は未実装で一度も実行されていなかった（立場を補強するもっともらしい理由の捏造）。
- **訂正ルール**: 「〜が起きた」と主張する前に、それが会話ログ・リポジトリで確認できる事実かを確かめる。立場を支える強い理由が事実でないなら、弱い方の真実をそのまま言う。

- **間違い**: 調査対象の外部リポジトリに結果ファイルの作成・計画ファイルのチェックボックス更新を提案した。
- **訂正ルール**: **Vault外は既定で読み取り専用**。Vault外への書き込みは毎回、対象と内容を示して明示の許可を得る。調査結果はチャットに出力し、転記はユーザーが行う。

## AI生成ノートの運用ルール（再調査ワークフロー）

Zettelkastenは手動で書くことに意味がある。AIが書いたノートは「人間が再調査するまで下書き」として扱う。AIが知識ノート（`Zettel/` など）を新規作成、または実質的に執筆した場合は必ず:

1. frontmatterに `ai_generated: YYYY-MM-DD`（生成日）を付ける。
   - 一覧は [[Registry/AI下書き一覧]] がdataviewで自動収集する。
   - 人間が手動で再調査し、自分の言葉で書き直したらこのプロパティを削除する（＝卒業）。AIは頼まれない限り削除しない。
2. 自信のない・一次情報未確認の記述には、本文に `⚠️未検証: 〜` と目印を書く。
3. この用途に**チェックボックス（`- [ ]`）を使わない**。TasksプラグインはVault内の全チェックボックスをタスクとして拾うため、日常のタスク一覧を汚染する。「要再調査」は行動（タスク）ではなくノートの状態なので、プロパティで表す。
4. ダッシュボード・設定ファイル・CLAUDE.md自体はこのルールの対象外（知識ノートのみ）。

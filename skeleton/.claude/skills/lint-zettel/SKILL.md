# Zettel化リンター

## 役割（診断であって自動化ではない）

ノートが完全なZettelの条件を満たすかを**診断し、具体的な直し方を提案する**。
Zettelの価値は人間が考えること（結びつけ・再定式化・取捨選択）にある。だからAIは**診断とサジェストまで。判断と確定は人間に返す。**

## 絶対にやらないこと（境界）

- リンク・分割・改題・タグ変更を**勝手に確定しない**。必ず提案として出し、承認を得てから編集する（CLAUDE.md「編集前に許可」に従う）。
- 本文を**自分の言葉に書き直して「卒業」扱いにしない**。再定式化は人間の仕事。
- `ai_generated` を**自分では外さない**（頼まれない限り）。

## 診断の観点（チェックリスト）

各項目を「達成／未達」で判定し、未達なら **何が／なぜ／どう直すか（具体案）** の3点を出す。優先度は上から高い。

0. **Zettel資格（ゲート・最優先）**: そもそも idea があるか。
   - 判定: 「**この内容は出典（仕様書・公式ドキュメント・memo）を読み直せば完全に再生成できるか？**」— できるなら Zettel 失格（仕様の写し／対象の記述の破片）。参照情報は memo か対象のアンカーノート1箇所に置き、ノート化しない。対象の記述を章単位で切った「Xの◯◯要素」型は破片の疑いが強い。
   - ただし判定は形式でなく**付加価値**で行う: 再生成不能な自分の判断・接続・観察が1行でもあれば idea の芽がある（タイトルが「Xの〜」でも中身が idea なら可）。
   - サジェスト: 失格でも中に idea が埋まっていれば、**その idea だけを主張のタイトルで切り出す**案を出す（カタログ部分は捨てて参照側へ）。
   - この観点は既存ノートの診断だけでなく、**新規作成前の候補のふるい分け**にも使う。
1. **接続（最重要）**: 出リンク・被リンクがあるか。孤立していないか。
   - サジェスト: Grep/Glob で vault 内の関連ノートを実際に探し、**存在するノートへの**リンク候補＋一言の接続理由を提示。被リンクは「どのノートから張り返すか」も提案。
2. **タイトル＝主張**: タイトルが中身の主張のハンドルになっているか。中身と食い違っていないか。
   - サジェスト: タイトル候補を数案。食い違うなら「改題」か「分割」かを提示。
3. **原子性**: 1ノート＝1アイデアか。複数の id が同居していないか。
   - サジェスト: 分割するなら、どこで切り、どちらを主／従にし、どうリンクし直すかの案。
4. **自己完結（autonomy）**: 単体で読んで意味が通るか。宙に浮いた前提・文脈依存の指示語はないか。
   - サジェスト: 補うべき定義・前提へのリンク候補。
5. **出典・参照**: 引用元が明記されているか。references が本文（自分の主張）と分離されているか。
6. **タグ**: object tag のみか（topic tag が混ざっていないか）。→ 詳細は CLAUDE.md 参照。
7. **`ai_generated` 衛生**: 下書き印の要否、`⚠️未検証` の要否。→ CLAUDE.md 参照。
8. **記法**: 数式が Typst か（LaTeX 混入なし）。→ CLAUDE.md 参照。

## サジェストの温度感（積極的に、ただし案として）

- リンク候補・タイトル候補・分割案などは **具体で積極的に出す**。抽象的な指摘だけで終わらせない。
- ただし各サジェストは **「案」であり採否は人間が決める** と明示する。
- リンク候補は必ず実在確認する（存在しないノートを提案しない）。

## 出力の形

- 「達成」項目は簡潔に。未達項目は優先度順に、上記3点セットで。
- 最後に「どれから着手するか」を人間に聞き、**編集は承認後**に行う。
- 手書き画像が生のまま貼ってあるだけの場合は、先に `transcribe-handwritten-note` での清書を促す。
